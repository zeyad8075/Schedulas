# FLUTTER_RUN_GUIDE.md
## Schedulas Flutter App — Run & Debug Guide

---

## ⚠️ Read this section first — it will otherwise cost you time

**This repository does not contain platform folders.** There is no
`android/`, `ios/`, `web/`, `linux/`, `macos/`, or `windows/` directory.
Only `lib/`, `pubspec.yaml`, `assets/`, and `l10n.yaml` exist. This is
because every file in this project was hand-written directly — `flutter
create` was never run to scaffold the project, since doing so requires
the actual Flutter SDK/toolchain, which was not available in the
environment that produced this code.

**You must generate the platform folders yourself before `flutter run`
will work at all.** From the `flutter_app/` directory:

```bash
flutter create --org com.schedulas --project-name schedulas .
```

Running `flutter create` on an existing directory with the `.` target
adds the missing platform scaffolding without touching your existing
`lib/`, `pubspec.yaml`, or `assets/` — but **review the diff/generated
files afterward** (especially `pubspec.yaml`, which `flutter create` may
attempt to regenerate parts of — back up your current `pubspec.yaml`
first if you want to be safe, and re-apply the dependency list in
§4 if anything gets overwritten). This step is not optional — everything
else in this guide assumes it has already been done.

Install a Flutter SDK whose bundled Dart SDK satisfies this (Flutter

```bash

```

## 2. Android SDK Requirements

Since platform folders don't exist yet, there is no `android/app/build.gradle`
with pinned `compileSdk`/`minSdk`/`targetSdk` values to report — those
will be generated by `flutter create` at whatever defaults your installed
Flutter SDK ships with. After running `flutter create`, check
`android/app/build.gradle` (or `build.gradle.kts`) and set:
- `minSdk`: at least 21 (required by `supabase_flutter`'s auth session
  handling and `flutter_secure_storage`); check both packages' own
  documentation for their current minimum, as this can change between
  package versions.
- `compileSdk` / `targetSdk`: whatever your installed Android SDK
  supports — Flutter's generated default is usually fine; only override
  if a specific plugin requires a newer one.

You'll also need: Android SDK Platform Tools, an Android emulator or
physical device, and (for a release build) a signing keystore — none of
which exist yet since no platform folder exists yet either.

## 3. Environment Configuration

Configuration is read at build/run time via `--dart-define`
(`lib/core/config/env_config.dart`) — **never hardcoded, and never read
from a `.env` file** (no `.env`-reading package is used). Missing values
cause the app to show a deliberate "configuration incomplete" screen
rather than run in a half-configured state (`main.dart`'s
`EnvConfig.isConfigured` check).

Required:
```
SUPABASE_URL=https://<project>.supabase.co
SUPABASE_ANON_KEY=<anon key>
API_BASE_URL=http://<host>:<port>/api/v1
```

`API_BASE_URL` must point at a **running Schedulas.API instance** — see
`BACKEND_RUN_GUIDE.md`. There is nothing for this app to talk to until
that's up. For an Android emulator talking to a backend running on your
host machine, use `http://10.0.2.2:<port>/api/v1`, not `localhost`.

## 4. Supabase Configuration

Same Supabase project as the backend (`BACKEND_RUN_GUIDE.md` §4) — this
app authenticates directly against Supabase Auth, not through the
Schedulas API. Nothing additional to configure on the Flutter side beyond
the URL/anon key passed via `--dart-define`.

## 5. Firebase Configuration

**Not yet integrated on the Flutter side.** The backend's push
notification delivery (`FcmPushNotificationService`) and the API endpoint
for registering a device token (`POST /notifications/device-tokens`,
wrapped by `NotificationsRepository.registerDeviceToken`) both exist and
work — but nothing in this Flutter app yet calls Firebase Messaging to
obtain an actual device token to register. Adding that requires:
1. Running `flutterfire configure` (after platform folders exist) to
   generate `firebase_options.dart` and register the app with your
   Firebase project.
2. Adding the `firebase_core` and `firebase_messaging` packages.
3. Calling `FirebaseMessaging.instance.getToken()` and passing the result
   to `registerDeviceToken` — a small, well-scoped addition once platform
   folders exist, not attempted here since it needs `flutterfire configure`
   run against a real toolchain.

## 10. `flutter run`

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://<project>.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=<anon key> \
  --dart-define=API_BASE_URL=http://10.0.2.2:<port>/api/v1
```

Select your target device/emulator when prompted, or pass `-d <device-id>`.

For a faster edit-reload loop during manual testing, `flutter run` alone
(without `--release`) enables hot reload — press `r` in the terminal
after a code change.

## 11. Common Issues and Fixes

| Symptom | Likely Cause | Fix |
|---|---|---|
| `flutter run` fails immediately, no device/build target found | Platform folders don't exist | Run `flutter create` per the warning at the top of this guide |
| App launches to a "configuration incomplete" screen | Missing/misspelled `--dart-define` value | Check all three required keys are passed exactly as named in §3 |
| Login succeeds but every screen shows "تعذّر تحميل..." (failed to load) errors | `API_BASE_URL` unreachable from the device/emulator | Confirm the backend is actually running (`BACKEND_RUN_GUIDE.md` §9); on Android emulator, `localhost` refers to the emulator itself, not your host — use `10.0.2.2` |
| Login fails with a generic Arabic error even with correct credentials | Supabase project's email confirmation is required and the test user hasn't confirmed their email | Check Supabase Auth settings, or manually confirm the user in the Supabase dashboard |
| `flutter analyze` reports errors in generated `l10n` files | `flutter gen-l10n` wasn't run, or was run before `flutter pub get` | Run `flutter pub get` then `flutter gen-l10n`, in that order |
| RTL layout looks mirrored incorrectly in specific widgets | A widget using a `left`/`right`-specific property instead of `start`/`end` (e.g. `EdgeInsets.only(left: ...)` instead of `EdgeInsetsDirectional`) | Search for raw `left`/`right` positional properties in the flagged widget's file; this codebase mostly uses symmetric/directional-safe padding already, but a real device/analyzer pass may surface an exception |
| Theme doesn't switch after changing it in Settings | `themeModeProvider` derives from `userSettingsProvider`, which is `autoDispose` — if no widget is actively watching it when you'd expect a refresh, it may not have re-fetched | Confirm `updateUserSettings` (in `settings_providers.dart`) is actually being awaited before navigating away; check for exceptions in the save flow first |
| `flutter build` (any platform) fails on a plugin needing a newer Android/iOS minimum | Same root cause as Android SDK requirements above — a dependency's minimum platform version exceeds what `flutter create`'s defaults set | Raise `minSdkVersion` (Android) or the iOS deployment target in the generated platform project files |
